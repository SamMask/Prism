# 派工 Prompt 模板

用法：主模型委派子任務時，選對應模板，填 `{{...}}`，整段貼進 subagent prompt。模板正文是工具中立的——Claude Code 用 Agent 工具派發；Codex 或無 subagent 環境時，把同一段當成「自我約束前綴」貼在自己的工作區開頭照做（紀律要能降級成 prompt，不綁特定 harness）。

Claude Code 派發參數建議（詳見 `治理/MODEL-DISPATCH.md` §3）：搜尋→`Explore`；實作/重構→general-purpose + `sonnet`；機械驗證→general-purpose + `haiku`；研究→general-purpose；審查→不低於施工者的模型。

每個模板都含三件套：目標與動機、驗收條件、回報格式。不要刪這三段。

---

## 1. 搜尋 / 盤點

```text
【目標與動機】在 {{repo 或目錄}} 找出 {{要找的東西：定義 / 呼叫點 / 慣例 / 設定}}。
動機：{{主任務為什麼需要這個答案}}。
【範圍與邊界】只讀不寫。跳過 {{node_modules、dist、build、產生檔等}}。
如果找到超過 {{N}} 處，只回最相關的前 {{N}} 處並說明還有多少。
【驗收條件】每個結論都附「檔案:行號」；找不到也要明說「確認不存在於 {{範圍}}」，
並列出你搜過的關鍵字與位置（證明找過，不是沒找）。
【回報格式】
結論：<直接回答問題，1-3 句>
關鍵位置：<檔案:行號 + 一句說明，逐條列>
相關慣例：<如有>
沒把握之處：<如有>
不要貼整檔內容。
```

## 2. 實作

```text
【目標與動機】實作 {{功能 / 修復}}：{{一段話說清楚行為}}。
動機：{{為什麼做、給誰用}}。
【計畫與規格】要改的檔案：{{清單}}。適用的規格 / 邊界條目原文：{{從權威文件貼進來，
subagent 是冷啟動，看不到主對話}}。
【邊界】最小變更；不順手重構、不加計畫外的抽象 / fallback / cache / log；
不動 {{禁區檔案}}。發現計畫與現況衝突 → 停下回報，不自己決定。
【驗收條件】{{可跑的測試指令}} 全綠；行為變更先有 failing test 再實作；
diff 中每一行都能對到本需求。
【回報格式】
完成層級：候選 / 本機通過（或：受阻 + 原因 + 已試過什麼）
做了什麼：<檔案:行號 + 一句，逐條>
測試：<指令> → N passed / M failed（失敗只貼關鍵行）
需主模型決定：<衝突或超範圍處，無則寫「無」>
不要宣稱「正式完成 / 已部署」——你的上限是「本機通過」。
```

## 3. 重構

```text
【目標與動機】重構 {{目標範圍}}：{{要消除的具體痛點，至少兩個已發生的案例}}。
動機：{{不重構會繼續付什麼代價}}。
【硬前提】行為不變。重構前先確認 {{測試指令}} 全綠並記下基準；
若現況就不綠，停下回報，不要在紅的基礎上重構。
【邊界】一次只做一種等價變換（搬移 / 改名 / 抽函式擇一），分步提交描述；
不改公開介面除非計畫明列；不「順便」修 bug——發現 bug 記下來回報，不修。
【驗收條件】重構後 {{測試指令}} 與基準相同全綠；公開介面 / 對外行為 diff 為零
（或列出計畫內的例外）。
【回報格式】
完成層級：候選 / 本機通過
變換清單：<每步一句：做了什麼等價變換、動了哪些檔>
測試：基準 <結果> → 重構後 <結果>
發現但未修的問題：<逐條，這是重要產出不是附註>
```

## 4. 研究

```text
【目標與動機】研究 {{問題}}，回答 {{明確的問題句}}。
動機：{{這個答案會決定什麼}}。
【方法邊界】可查 {{來源範圍：官方文件 / repo / 網頁}}。區分三種內容並標明：
(a) 有來源的事實（附 URL 或檔案位置）、(b) 你的推論、(c) 查不到的空白。
禁止把推論寫成事實；查不到就寫查不到。
【驗收條件】問題句有直接答案（或明確回答「無法確定 + 缺什麼」）；
每個關鍵事實可溯源；有至少一段「反方證據 / 例外情況」。
【回報格式】
答案：<1-3 句直接回答>
依據：<事實 + 來源，逐條>
反方 / 例外：<至少一條，真的沒有就說明為何沒有>
信心：高 / 中 / 低 + 一句原因
長篇材料落檔到 {{路徑}}，回報只給路徑與摘要。
```

## 5. 審查 / 驗收

```text
【目標與動機】以 fresh context 驗收 {{工作產出}}。你沒有參與施工，
這正是你的價值：不要採信施工者的回報，只採信你自己驗出來的。
【驗收條件】（主模型填，逐條可檢查）
1. {{條件一，例：X 檔存在且包含 Y 章節}}
2. {{條件二，例：測試指令 Z 全綠}}
3. {{條件三，例：diff 不含需求外變更}}
【驗法】檔案主張用 read-back（自己重讀檔案）；行為主張用實跑（自己跑指令）；
引用的路徑 / 檔名 / 章節逐一確認存在。不確定的標「無法驗證」而不是放行。
【回報格式】
逐條判定：<條件 N：通過 / 不通過 / 無法驗證 + 證據>
發現的其他問題：<超出驗收條件但明顯的錯，逐條 + 檔案:行號>
總判定：通過 / 退回（退回必附最小修復清單）
```

## Codex 環境使用備註

- Codex 不會讀 `.claude/agents/*.md`，也沒有本環境的 Agent 工具；是否有原生子任務能力以當前 session 實際可用為準。
- 有子任務能力：模板整段貼進子任務 prompt，照用。
- 沒有：模板當自我約束前綴——先把三件套寫出來再動手，完成後自己跑一次模板 5 的驗收段（此時已違反「驗證不自驗」，要在回報中明說「本輪為自驗，可信度較低」）。
- 模型升降級照 `治理/MODEL-DISPATCH.md` §6 的原則執行，但型號對照表不適用；用「當前環境最便宜可勝任 / 主力 / 最強」三檔對應。
