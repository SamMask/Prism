## 一、三件最重要的事

### 1. 你有跨 session 記憶，用它，不要靠重讀大文件傳承

這個 harness 有檔案式 memory（`C:\Users\USER\.claude\projects\D--AI-000-LLM------\memory\`，索引在 `MEMORY.md`），另外環境裡還有 mempalace MCP 可查。跨 session 該傳承的是「使用者偏好、環境的坑、非顯而易見的決策原因」——這些寫進 memory 一次，之後每個 session 自動受益；寫進母模板反而污染模板的可搬用性。分界線：會跟著使用者走的進 memory，會跟著專案走的進治理文件。

### 2. 這位使用者要的是誠實的狀態，不是漂亮的產出

整個母模板庫的核心痛點只有一個：LLM 誤報完成。對這位使用者，「查證後不需要改」「目前做不到，缺 X」「本輪只到本機通過」都是合格答案，而且比硬湊產出得分高。溝通用簡單繁體中文、先講結論、短答優先。使用者的專案由 Claude 與 Codex 輪流開發，所以任何你寫下的規格與邊界，要放在專案自己的治理文件裡讓兩邊都看得到，不要藏在單邊工具設定。

### 3. 這個環境的故障模式是暫時性的，不要把它當成你的錯

實際發生過：權限分類器暫時故障導致 PowerShell 呼叫被拒（錯誤訊息會寫明 temporarily unavailable）。遇到工具被拒先讀錯誤原文——是暫時故障就換等效工具（檔案工具、Bash）或稍後重試，不是重寫你的指令重試十次。同理，CRLF 警告、git 的 octal escape 路徑都是環境常態（見 CLAUDE.md 本機環境備忘），不是待修 bug。

## 二、這套制度最可能的退化方式與預防

1. **規則回膨脹**：每次踩坑加一條、沒人刪，規則清單長回「讀完抓不到重點」的狀態——這正是本次改版要解決的問題。預防：`治理/MAINTENANCE-PROTOCOL.md` §5 的長度預算是硬上限；新增規則必須帶觸發條件與案例，否則視為口號拒收。
2. **路由檔再度長胖**：CLAUDE.md 最方便，大家都想往裡塞。預防：10KB 上限；超過就把內容下放，CLAUDE.md 只留「什麼任務 → 讀哪裡」。
3. **儀式化（最危險）**：弱模型學會照抄回報格式——寫「驗證：read-back 通過」但其實沒讀。格式對了、行為沒發生，制度就變成偽裝。預防：驗收回報必須含證據原文（實際跑的指令 + 實際輸出），只有格式沒有證據的回報一律視為未驗證；審查者要抽查證據是否真能重現。
4. **同步機制無人執行**：SYNC-BLOCK 標記沒人加、版本號沒人動，三份母模板靜默漂移。預防：交接區有此待辦；任何 session 動到共用塊時順手把標記補上。
5. **制度與 harness 脫節**：工具改名、模型換代後，文件裡的型號與參數變成錯誤指引。預防：`治理/MODEL-DISPATCH.md` §0 標了驗證日期——引用失效時按 MAINTENANCE §1 自行修正並更新日期，這屬於可自行改的範圍。

## 三、誠實條款（制度的極限）

拆解、驗證、fresh-context 審查、多答案評審，補得了執行品質；補不了模糊題與品味判斷（架構取捨、UX 品味、文字語感）。弱模型遇到品味題的正確動作，依序是：升級模型、要求外部第二意見、或明說「這題我的判斷不可靠，建議人工決定」。這三個都是合規出口；硬給一個自信的答案才是違規。
